# MICROCPU Assembler and ISA Reference (from source)

This document is generated by analysis of `microasm.c` (assembler behavior and
encoding) and `rtl/cpu.v` (execution semantics). The assembler implementation is
the source of truth for syntax and encoding. The RTL is the source of truth for
runtime behavior.

## 1. ISA Overview

### Registers
The assembler recognizes eight general registers with numeric indices 0..7 and
aliases (case-insensitive):

- `r0` (alias `pc`)
- `r1` (alias `sp`)
- `r2` (alias `lr`)
- `r3` (alias `v0`)
- `r4` (alias `v1`)
- `r5` (alias `v2`)
- `r6` (alias `v3`)
- `r7` (alias `v4`)

### Address space
The assembler output buffer is 64 KiB (`output[65536]`). Addresses are treated
as 16-bit byte addresses, and output generation fails with `OUTPUT_BUFFER_OVERFLOW`
if it exceeds 65535.

### Instruction word size
All ISA instructions emitted by the assembler are exactly 1 word = 2 bytes.

### Execution model (RTL-derived)
- `r0` is the program counter (PC) in **byte** units.
- PC increments by 1 each cycle by default.
- Instruction execution occurs when `r0[0] == 1` (odd byte). The opcode/operands
  are latched when `r0[0] == 0` (even byte).
- The branch instruction encodes a signed word offset; PC update aligns to even
  byte then adds `offset << 1`.
- Memory operations use `R[arg1] + (const4 or R[arg2])` as the address.
- `const4` is a 4-bit immediate. Values are truncated in hardware to 4 bits.

Superuser mode:
- `sws` requests a switch to superuser mode.
- When a request or external interrupt occurs, `user_pc` is saved and PC jumps
  to `0x0002`.
- `swu` restores `user_pc` and returns to user mode.
- `setp`/`getp` write/read `user_pc`.

## 2. Assembler Syntax

### Lexical rules
- Case-insensitive for mnemonics, labels, registers, and directives
  (`strcasecmp` is used throughout).
- Tokens are separated by ASCII blanks (`isblank`), i.e. spaces and tabs.
- Lines may contain an optional label, then an opcode/mnemonic or macro name,
  followed by operands.

### Identifiers and labels
- Label and symbol definitions are parsed with `SKIP_TOKEN`:
  - First character must be `A-Z`/`a-z`, `_`, `:` or `.`
  - Subsequent characters may be alphanumeric or `_`
- Label references inside expressions are parsed with a slightly looser rule
  (alphanumeric, `_`, `:`, `.`), but they must match a previously defined name.
- Labels are case-insensitive. Duplicate labels are errors.

### Numbers and literals
- Decimal: `123`
- Hex: `$1f` (prefix `$`)
- Octal: `@17` (prefix `@`)
- Binary: `%1010` (prefix `%`), underscores allowed: `%1010_0001`
- Character literal: `'<c>'` or `'<c>` (closing quote is optional in code)
- Current address: `*` in expressions evaluates to the current output address

### Comments
- `;` and `//` start a comment, unless inside `'...'` or `"..."` strings.

### Strings
- In `db`, strings may be in single or double quotes. No escape sequences are
  implemented; characters are copied verbatim until the closing quote.

### Expressions
Expression grammar and precedence (highest to lowest), as implemented:

1. Parentheses: `( ... )`
2. Unary: `~` (bitwise not), `-` (negation)
3. Multiplicative: `*`, `/`, `%`
4. Additive: `+`, `-`
5. Bitwise AND: `&`
6. Bitwise XOR: `^`
7. Bitwise OR: `|`

Special case: if an expression starts with `/` (slash), the value is
`exp >> 8` (high byte extraction). This is used by macros such as `set`.

Division or modulo by zero yields `SYNTAX_ERROR`.

### Statements and line structure
- A line can be:
  - empty or comment-only
  - a label alone
  - a label followed by an opcode/directive/macro call
  - an opcode/directive/macro call without a label
- A label and opcode can share a line: `label opcode args...`
- A label may also be written as `label:` (colon is treated as a separator)

## 4. Instruction Reference

### Encoding conventions
All instructions are encoded as two bytes:

- byte0 = `(op << 3) | (arg1 & 0x07)`
- byte1 = `((arg2 << 5) & 0xE0) | (arg3 & 0x1F)`

Operand-to-arg mappings:

- op_reg_const (`setl`, `seth`):
  - arg1 = destination register
  - arg2:arg3 = immediate (8-bit), split across high/low bits
  - No range check; values are truncated to 8 bits.

- op_reg_reg (`movl`, `movh`, `mov`, `sxt`, `inv`):
  - arg1 = destination register
  - arg2 = source register
  - arg3 = 0

- op_reg (`setp`, `getp`, `getf`):
  - arg1 = register
  - arg2 = arg3 = 0

- op_reg_reg_reg (`ldrl`, `strl`, `ldr`, `str`, `add`, `sub`, `subb`,
  `shl`, `shr`, `and`, `or`, `xor`):
  - arg1 = destination register
  - arg2 = source register
  - arg3 = either:
    - register form: `(reg << 2)`
    - immediate form: `((imm4 & 0x0F) << 1) | 0x01`
  - Immediate is accepted when the third operand is not a register.
  - If immediate > 16, the assembler errors with `CONSTANT_VALUE_TOO_BIG`.
  - Immediate value 16 is accepted by the assembler but truncates to 0 in
    hardware due to 4-bit width.

- op_ext_reg_reg (`eq`, `ne`, `mi`, `vs`, `lt`, `ge`, `ltu`, `geu`, `btc`, `bts`):
  - arg1 = ext_op (3-bit sub-opcode, from the mnemonic table)
  - arg2 = first register operand
  - arg3 = register or immediate form (same encoding as op_reg_reg_reg)
  - Immediate > 16 errors with `CONSTANT_VALUE_TOO_BIG`.
  - Immediate value 16 truncates to 0 in hardware due to 4-bit width.

- op_rel (`b`):
  - The expression is evaluated to a byte address, then `val = target - output_addr`.
  - Range check: `val` must be in [-0x7ff, 0x7ff] (bytes).
  - The encoded offset is `val >> 1` (word address).
  - In hardware, the branch adds `sign_extend(11-bit) << 1` to the aligned PC.

### CPU / Mode Control

`gget` and `gset` are aliases used only by `rtl/j11_microengine.v`. They reuse
the `sws` and `swu` opcode groups respectively; the original `rtl/cpu.v`
continues to interpret those groups as mode-control instructions.

`JCTX` below is an address-space convention, not a separate RTL register
array. On the HC1200 microengine its 64 words occupy the tail of the shared
microcode EBR RAM (`UROM_WORDS - 64` through `UROM_WORDS - 1`). Native accesses
cannot write the code region. Cause/IRQ/control indexes 10/11/15 remain
service ports; architectural register layout and bank switching are firmware.
Context accesses retain the ordinary six-clock instruction timing.

#### gget
- Syntax: `gget R, I8`
- Encoding: op = 0x12, op_reg_const
- Microengine semantics: `R[dest] = JCTX[I8 & 0x1f]`

#### gset
- Syntax: `gset R, I8`
- Encoding: op = 0x14, op_reg_const
- Microengine semantics: `JCTX[I8 & 0x1f] = R[src]`

#### ggetr
- Syntax: `ggetr Rdest, Rindex`
- Encoding: op = 0x18, op_reg_reg
- Microengine semantics: `Rdest = JCTX[Rindex & 0x3f]`
- The original `cpu.v` continues to use this opcode group for `setp`.

#### gsetr
- Syntax: `gsetr Rsrc, Rindex`
- Encoding: op = 0x1a, op_reg_reg
- Microengine semantics: `JCTX[Rindex & 0x3f] = Rsrc`
- Indexed access reaches all 64 context words. Immediate `gget`/`gset`
  retain their five-bit index (0..31); context meanings remain firmware-defined.
- The original `cpu.v` continues to use this opcode group for `getp`.

#### getf
- Syntax: `getf R`
- Encoding: op = 0x1C, op_reg
- Microengine semantics: `R[dest] = {12'b0, NZVC}` from the most recent
  data-producing ALU operation. Compare/bit-test skip operations do not replace
  the saved flags, so microcode can branch between an ALU operation and `getf`.
- This opcode is implemented only by `rtl/j11_microengine.v`; the original
  `rtl/cpu.v` is unchanged.

#### sws
- Syntax: `sws`
- Encoding: op = 0x12, op_noargs
- Semantics: request switch to superuser mode; actual switch occurs on next
  cycle when not already in super mode.
- Examples:
  - `sws`
  - `sws` ; repeated

#### swu
- Syntax: `swu`
- Encoding: op = 0x14, op_noargs
- Semantics: `PC = user_pc`, exit superuser mode, clear request flag
- Examples:
  - `swu`
  - `swu` ; repeated

#### setp
- Syntax: `setp R`
- Encoding: op = 0x18, op_reg
- Semantics: `user_pc = R[dest]`
- Examples:
  - `setp v0`
  - `setp r7`

#### getp
- Syntax: `getp R`
- Encoding: op = 0x1A, op_reg
- Semantics: `R[dest] = user_pc`
- Examples:
  - `getp v0`
  - `getp r7`

## 5. Assembler Directives (pseudo-operations)

These mnemonics are not ISA instructions; they are assembler directives.

### `equ`
- Syntax: `<symbol> equ <expression>`
- Effect: defines a constant symbol. Scope is global unless inside `proc`.
- Constraints: symbol must not already exist (case-insensitive).

### `db`
- Syntax: `db <item>[, <item>...]`
- `<item>` may be an expression or a quoted string.
- Effect: emits bytes; strings emit one byte per character.
- Constraints: output buffer must not exceed 65536 bytes.

### `dw`
- Syntax: `dw <expr16>[, <expr16>...]`
- Effect: emits 16-bit words, little-endian (low byte then high byte).

### `ds`
- Syntax: `ds <count>[, <fill>]`
- Effect: reserves `count` bytes filled with `<fill>` (default 0).

### `align`
- Syntax: `align <bits>`
- Effect: advances the output address to the next boundary derived from `bits`.
- Constraints: implemented as:
  - `n = 1 << bits; if (n > 1) n = n - 1;`
  - `count = ((addr + n) & ~n) - addr;`
  - Then emit `count` fill bytes (0).
- Note: `bits = 0` and `bits = 1` both align to an even address in code.

### `org`
- Syntax: `org <address>`
- Effect: sets the output address counter and start address.

### `include`
- Syntax: `include <path>`
- Effect: includes another source file. The assembler prepends the current
  input file directory to the provided path.
- Constraints: no quoting or escape processing is implemented.

### `chksum`
- Syntax: `chksum`
- Effect: reserves two bytes and, after pass 2, inserts a 16-bit checksum.
- Checksum algorithm: sum all 16-bit words from `start_addr` to `output_addr`
  (inclusive of the reserved word), then bitwise invert (`^ 0xFFFF`).

### `extern`
- Syntax: `extern <symbol>[, <symbol>...]`
- Effect: declares symbols defined by another object module.
- Constraints: only valid with `-object` output. External symbols may be used in
  absolute byte/word operands, but not in relative branches or other fields that
  cannot be relocated.

### `public`
- Syntax: `public <symbol>[, <symbol>...]`
- Effect: exports labels or constants from the current object module.
- Constraints: only valid with `-object` output. Every public symbol must be
  defined by the end of assembly.

### `entry`
- Syntax: `entry <expression>`
- Effect: stores the object entry point in the object header.
- Constraints: only valid with `-object` output. The expression must resolve to
  an address inside the generated code segment and cannot reference an external
  symbol. If `entry` is omitted, the object header entry point is `$FFFF`
  (none).
- Compatibility: `end` is not a directive; existing sources may use `end` as a
  label.

### Conditional assembly
- Syntax:
  - `IF <expression>`
  - `IFDEF <symbol>`
  - `IFNDEF <symbol>`
  - `ELSE`
  - `ENDIF`
- Effect: controls which source lines are assembled. Disabled lines are not
  parsed as labels, directives, macros, or instructions.
- Conditions are evaluated during pass 1. Pass 2 replays the pass-1 decisions.
- `IF` treats any non-zero expression value as true. The expression must be
  resolvable in pass 1.
- `IFDEF` and `IFNDEF` test labels, constants, procedures, and macros that have
  already been seen by pass 1, including command-line defines.
- Nesting limit: 32 conditional levels.

### Object Output
- Syntax: `microasm -object <input_file> [output_file]`
- Alias: `-obj`
- Default extension: `.obj`
- Format: UniCROSS-style object file:
  - magic `$5AA5`, version `$0001`
  - internal (`public`) and external (`extern`) symbol tables
  - one code segment
  - relocation records for words, low bytes, and high bytes
- The assembler currently emits no separate data segment; the object data
  length field is zero.
- `org` and `chksum` are rejected in object output.
- High-byte relocations (`/symbol`) add the linked symbol high byte to the
  encoded high byte. Expressions that require carry propagation across split
  low/high relocations should use a word relocation instead.

## 6. Macros and Procedures

### Macros
- Syntax:
  - `macro <name>`
  - `...`
  - `endm`
- Parameters:
  - Call arguments are comma-separated.
  - Inside the macro body, `#1`..`#9` are replaced with corresponding arguments.
- Notes/Limitations:
  - No argument count checking is performed.
  - `#0` or `#` followed by a non-digit is not handled safely.
  - Macro expansion is purely textual; no escape mechanism exists.

### Procedures
- Syntax:
  - `<name> proc`
  - `...`
  - `endp`
  - `global <label>[, <label>...]` (inside a proc only)
- Scoping:
  - Labels and `equ` symbols inside a proc are stored in per-proc lists.
  - If a label name was declared as `global` before its definition, the label
    is also added to the global label table when defined.
- Limitations:
  - Nested procedures are rejected (`NESTED_PROC_UNSUPPORTED`).
  - `global` outside a proc is an error (`ONLY_INSIDE_PROC`).
  - `global` is procedure-local visibility, not an object export directive.
    Use `public` to export object symbols.

## 7. Command-Line Interface

Usage (as implemented):

```
microasm [-verilog|-binary|-object] [--list <file|->] [-D name[=expr]|--define name[=expr]] [-U name|--undef name] <input_file> [output_file]
microasm [-verilog|-binary|-obj] [--list=<file|->] [-Dname[=expr]|--define=name[=expr]] [-Uname|--undef=name] <input_file> [output_file]
```

- `-verilog`: output a Verilog `sram` module with memory initialization.
- `-binary`: output raw binary bytes.
- `-object` / `-obj`: output an object file for `microlink`.
- default: output a `.mem` hex file with address and bytes.
- `--list <file|->`: write the assembly listing to a file, or to stdout when
  the argument is `-`. By default no listing is printed. Compilation status and
  error lines are always printed to stdout and, when `--list` is used, to the
  listing stream. The final `Constants`, `Labels`, and `Refs` tables are
  included only there.
- `-D` / `--define`: define a global constant before pass 1. If `=expr` is
  omitted, the value is `1`. The expression may reference earlier command-line
  defines.
- `-U` / `--undef`: remove a command-line define before pass 1.

If `output_file` is omitted, the assembler derives it from the input name and
appends `.v`, `.bin`, `.obj`, or `.mem` depending on the output type.

### `microlink`

Usage:

```
microlink [-verilog|-binary] [-symbols] [-org address] [-o output_file] <input.obj>...
```

- default: output a `.mem` hex file with address and bytes.
- `-binary`: output raw binary bytes.
- `-verilog`: output a Verilog `sram` module with memory initialization.
- `-symbols` / `--symbols`: print the resolved public symbol table to stdout.
- `-org <address>`: base address for the linked code image (default `$0000`).
- `-o <output_file>`: explicit output path. If omitted, the linker derives the
  output name from the first object input.

`microlink` consumes one or more object files, concatenates their code segments
in input order, resolves `extern` references from `public` symbols, applies
relocations, and writes a final non-relocatable output image. It does not emit
relocatable output files.

### `microdis`

Usage:

```
microdis [-binary|-object] [-org address] <input.bin|input.obj>
```

- default input mode is auto-detect: object files are recognized by their
  `$5AA5`/version header, otherwise the input is treated as raw binary.
- `-binary`: force raw binary input.
- `-object` / `-obj`: force object input.
- `-org <address>`: base address shown in disassembly (default `$0000`).

`microdis` writes disassembly to stdout. For object files it also prints
`extern`/`public` declarations, absolute exported constants, the object entry
point, labels from the public symbol table, and relocation comments. It does
not infer which bytes are data; without debug metadata every two-byte word is
decoded as an instruction, with a trailing odd byte emitted as `db`.

## 9. Source-of-Truth Notice

Assembler syntax and encoding details come from `microasm.c`.
Execution semantics come from `rtl/cpu.v`.
If hardware behavior differs from this document, the RTL wins for runtime
behavior, and the assembler wins for parsing/encoding.
